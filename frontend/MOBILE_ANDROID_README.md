## 1. Overview

SmartAdopt uses **Capacitor v8** to wrap its React + Vite web application inside a native Android shell. The overall flow is:

```
React / Vite source (src/)
        │
        ▼  npm run build
   dist/  (web bundle)
        │
        ▼  npx cap sync android
  android/  (native Android project)
        │
        ▼  Gradle assembleXxxRelease / Android Studio
     .apk  (installable package)
```

The Android project lives at `frontend/android/` and is a standard Gradle project that Capacitor manages automatically whenever you run `npx cap sync android`.

## 4. Capacitor Configuration

**File:** [`frontend/capacitor.config.ts`](./capacitor.config.ts)

```ts
import type { CapacitorConfig } from '@capacitor/cli';

const config: CapacitorConfig = {
  appId: 'net.programacionwebuce.smartadopt',   // Base package name (Production)
  appName: 'SmartAdopt',
  webDir: 'dist'                                 // Output directory of `npm run build`
};

export default config;
```

- **`appId`** is the base Android package name. Build flavors add a suffix for non-production environments (e.g. `.local`, `.qa`).
- **`webDir`** tells Capacitor where to find the compiled web bundle to copy into the Android `assets/` folder.

## 5. Android Build Flavors

The Android project defines **three product flavors** under a single `environment` dimension in [`app/build.gradle`](./android/app/build.gradle):

| Flavor | Application ID | Version Suffix | Signing | Purpose |
|--------|---------------|----------------|---------|---------|
| `local` | `net.programacionwebuce.smartadopt.local` | `-LOCAL` | Debug (unsigned) | Local development |
| `qa` | `net.programacionwebuce.smartadopt.qa` | `-QA` | `qa-release.keystore` | QA testing via Firebase |
| `prod` | `net.programacionwebuce.smartadopt` | *(none)* | `prod-release.keystore` | Production distribution |

> The signing configs for `qa` and `prod` are only applied when the corresponding environment variables (`QA_KEYSTORE_PASSWORD` / `PROD_KEYSTORE_PASSWORD`) are present. In CI these are injected as GitHub Secrets; locally they are absent, so the debug key is used automatically for the `local` flavor.

### Gradle SDK versions (`variables.gradle`)

```groovy
minSdkVersion     = 24    // Android 7.0+
compileSdkVersion = 36
targetSdkVersion  = 36
```

## 6. Running Locally with Android Studio

### Step 1 — Install dependencies

From the `frontend/` directory:

```bash
npm install
```

### Step 2 — Build the web bundle

```bash
npm run build
```

This runs `tsc -b && vite build` and outputs the compiled assets to `frontend/dist/`.

> **Tip:** The `VITE_API_URL` environment variable controls which backend the app connects to. For local API development you can set it to your local backend:
>
> ```bash
> VITE_API_URL=http://localhost:8000/api npm run build
> ```

### Step 3 — Sync the Android project

```bash
npx cap sync android
```

This command:
1. Copies the `dist/` bundle into `android/app/src/main/assets/public/`.
2. Updates native plugins.
3. Generates/updates `capacitor.settings.gradle` and `capacitor.build.gradle`.

### Step 4 — Open in Android Studio

```bash
npx cap open android
```

This opens the `frontend/android/` folder in Android Studio as a native Gradle project.

Alternatively, you can open it manually:
- Launch **Android Studio**
- Choose **Open** → navigate to `frontend/android/`

### Step 5 — Select the run configuration

In Android Studio:
1. Go to **Build > Select Build Variant**.
2. In the **Build Variants** panel, select **localDebug** for the `:app` module.
3. Choose a connected device or an AVD (Android Virtual Device / emulator).
4. Press **Run ▶**.

> **Build Variant to use locally:** `localDebug` — this uses the `local` flavor with the debug signing key, so no keystore setup is needed.

### Step 6 — Iterating during development

Every time you change React source code, repeat steps 2 and 3 before running again from Android Studio:

```bash
npm run build && npx cap sync android
```

## 7. CI/CD — QA Pipeline

**Workflow file:** [`.github/workflows/deploy-qa-mobile.yml`](../.github/workflows/deploy-qa-mobile.yml)

### Trigger

- **Automatic:** Any push to the `qa` branch.
- **Manual:** Via **Actions > Deploy QA Mobile > Run workflow** in GitHub.

### Concurrency

Only one QA mobile job runs at a time. A new push cancels any in-progress build (`cancel-in-progress: true`).

### Pipeline Steps

```
1. Checkout code
        │
2. Set up Node 20  (npm cache keyed to frontend/package-lock.json)
        │
3. npm ci  (install frontend deps)
        │
4. npm run build  ──► VITE_API_URL=https://smartadoptqa.programacionwebuce.net/api
        │
5. npx cap sync android  (copy dist/ → android assets)
        │
6. Set up JDK 17 (Temurin)
        │
7. Set up Android SDK
        │
8. Decode QA keystore  (base64 secret → qa-release.keystore)
        │
9. chmod +x gradlew
        │
10. ./gradlew assembleQaRelease  ──► signed APK
        │
11. Upload to Firebase App Distribution  (group: qa-testers)
        │
12. Upload APK as GitHub workflow artifact (retained 14 days)
```

### Output APK path

```
frontend/android/app/build/outputs/apk/qa/release/app-qa-release.apk
```

### Firebase Distribution

- **App ID:** secret `FIREBASE_APP_ID_QA`
- **Tester group:** `qa-testers`
- **Release notes:** include the triggering commit SHA and branch name.

### GitHub Artifact

The APK is also uploaded as a workflow artifact named:

```
smartadopt-qa-mobile-<commit-sha>
```

It is retained for **14 days** and can be downloaded from the **Actions** tab of the repository.

## 8. CI/CD — Production Pipeline

**Workflow file:** [`.github/workflows/deploy-prod-mobile.yml`](../.github/workflows/deploy-prod-mobile.yml)

### Trigger

- **Automatic:** Any push to the `main` branch.
- **Manual:** Via **Actions > Deploy Production Mobile > Run workflow** in GitHub, with an optional `track` input (`internal` | `production`, default: `internal`).

### Concurrency

Production builds are **never cancelled** mid-flight (`cancel-in-progress: false`) to prevent partially distributed releases.

### Pipeline Steps

```
1. Checkout code
        │
2. Set up Node 20  (npm cache keyed to frontend/package-lock.json)
        │
3. npm ci  (install frontend deps)
        │
4. npm run build  ──► VITE_API_URL=https://smartadoptprod.programacionwebuce.net/api
        │
5. npx cap sync android  (copy dist/ → android assets)
        │
6. Set up JDK 17 (Temurin)
        │
7. Set up Android SDK
        │
8. Decode Production keystore  (base64 secret → prod-release.keystore)
        │
9. chmod +x gradlew
        │
10. ./gradlew assembleProdRelease  ──► signed APK
        │
11. Upload to Firebase App Distribution  (group: prod-testers)
        │
12. Attach APK to GitHub Release  (tag: mobile-<commit-sha>)
```

### Output APK path

```
frontend/android/app/build/outputs/apk/prod/release/app-prod-release.apk
```

### Firebase Distribution

- **App ID:** secret `FIREBASE_APP_ID_PROD`
- **Tester group:** `prod-testers`

### GitHub Release

A GitHub Release tagged `mobile-<commit-sha>` is created automatically with the APK attached, using the PAT stored in `GH_PAT`.

## 9. Required GitHub Secrets

Configure the following secrets in **GitHub → Repository → Settings → Secrets and variables → Actions**:

| Secret | Used in | Description |
|--------|---------|-------------|
| `ANDROID_KEYSTORE_QA_BASE64` | QA | Base64-encoded QA keystore file |
| `ANDROID_KEYSTORE_QA_PASSWORD` | QA | Password for the QA keystore |
| `ANDROID_KEY_ALIAS_QA` | QA | Key alias inside the QA keystore |
| `ANDROID_KEY_PASSWORD_QA` | QA | Key password for the QA alias |
| `FIREBASE_APP_ID_QA` | QA | Firebase App ID for the QA app |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | QA & Prod | Firebase service account JSON (for App Distribution) |
| `ANDROID_KEYSTORE_PROD_BASE64` | Prod | Base64-encoded Production keystore file |
| `ANDROID_KEYSTORE_PROD_PASSWORD` | Prod | Password for the Production keystore |
| `ANDROID_KEY_ALIAS_PROD` | Prod | Key alias inside the Production keystore |
| `ANDROID_KEY_PASSWORD_PROD` | Prod | Key password for the Production alias |
| `FIREBASE_APP_ID_PROD` | Prod | Firebase App ID for the Production app |
| `GH_PAT` | Prod | GitHub Personal Access Token (to create GitHub Releases) |

### How to encode a keystore as Base64

On Linux/macOS:
```bash
base64 -i your-release.keystore | tr -d '\n'
```

On Windows (PowerShell):
```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("your-release.keystore"))
```

Paste the resulting string as the secret value.

## 10. Downloading the APK from Firebase App Distribution

### For QA testers

1. You must be added to the **`qa-testers`** group in the Firebase project **`smartadoptqa`**.
2. Accept the email invitation sent by Firebase.
3. Install the **Firebase App Distribution** app on your Android device — or use the link in the invitation email.
4. Inside the Firebase App Distribution app, you will see the latest SmartAdopt QA build available for download.

**Firebase project:** `smartadoptqa` (Project number: `833989929033`)
**QA package name:** `net.programacionwebuce.smartadopt.qa`

### For Production testers

1. You must be added to the **`prod-testers`** group in the Firebase project.
2. Accept the email invitation sent by Firebase.
3. Download and install the APK from the link in the invitation email, or through the Firebase App Distribution app.

**Production package name:** `net.programacionwebuce.smartadopt`

### Enabling installation from unknown sources (if needed)

Since the APK is distributed outside the Play Store, you may need to allow installations from unknown sources on your device:
- **Android 8.0+:** Go to **Settings → Apps → Special app access → Install unknown apps** and allow the browser or file manager you use to install APKs.

### Downloading from GitHub Actions (QA only)

The QA APK is also uploaded as a workflow artifact for 14 days:

1. Go to the GitHub repository.
2. Click **Actions** in the top navigation.
3. Select the **Deploy QA Mobile** workflow.
4. Click the latest successful run.
5. Scroll down to **Artifacts** and download `smartadopt-qa-mobile-<sha>`.

### Downloading from GitHub Releases (Production)

The Production APK is attached to every GitHub Release:

1. Go to the GitHub repository.
2. Click **Releases** in the right sidebar.
3. Find the release tagged `mobile-<sha>` corresponding to your commit.
4. Download the `.apk` file from the **Assets** section.

## 11. Key Files Reference

| File | Description |
|------|-------------|
| `frontend/capacitor.config.ts` | Capacitor app ID, name, and web bundle directory |
| `frontend/android/app/build.gradle` | Android build config: flavors, signing configs, SDK versions, dependencies |
| `frontend/android/variables.gradle` | Shared Gradle variables (SDK levels, library versions) |
| `frontend/android/build.gradle` | Root Gradle file: classpath plugins (AGP, google-services) |
| `frontend/android/settings.gradle` | Module includes (`:app`, `:capacitor-cordova-android-plugins`) |
| `frontend/android/capacitor.settings.gradle` | Auto-generated — links `capacitor-android` library from `node_modules` |
| `frontend/android/app/capacitor.build.gradle` | Auto-generated — Java compile options and Capacitor plugin deps |
| `frontend/android/app/google-services.json` | Firebase configuration for QA and Production package names |
| `frontend/android/app/src/main/AndroidManifest.xml` | App manifest: permissions (`INTERNET`), activity config |
| `frontend/android/gradle.properties` | Gradle JVM args and AndroidX flag |
| `.github/workflows/deploy-qa-mobile.yml` | CI pipeline: builds and distributes the QA APK |
| `.github/workflows/deploy-prod-mobile.yml` | CI pipeline: builds and distributes the Production APK |

---

> **Note on auto-generated files:** The files `capacitor.settings.gradle`, `capacitor.build.gradle`, and the contents of `android/app/src/main/assets/` are fully managed by the Capacitor CLI. **Do not edit them manually.** They are regenerated every time you run `npx cap sync android`.
